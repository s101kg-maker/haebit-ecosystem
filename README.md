# 해빛이의 생태계 인사발령

초등학교 4학년 과학 「생물과 환경」 활동 1에 사용하는 실시간 웹앱입니다.
**학생들의 선택과 근거를 모으며, 정답이나 생물의 역할 용어를 공개하지 않습니다.**

## 가장 먼저 할 일

1. 먼저 별도 제공된 `해빛이_디자인_미리보기.html`을 더블클릭하면 서버 설치 없이 바뀐 화면을 확인할 수 있습니다.
2. ZIP 파일을 풀어 주세요.
3. GitHub에 이 폴더 안의 파일을 올려 주세요.
4. Render에서 **Web Service**로 연결해 주세요.
5. `TEACHER_PIN`을 설정하면 수업을 시작할 수 있습니다.

HTML 파일을 더블클릭해서는 실시간 수업을 사용할 수 없습니다. Render 또는 Node.js 서버를 실행해야 합니다.

## GitHub에 올리기 — 웹사이트에서 하기

1. GitHub에 로그인합니다.
2. 오른쪽 위 `+` → **New repository**를 누릅니다.
3. Repository name에 `haebit-ecosystem`을 입력합니다. Public 또는 Private 모두 가능합니다.
4. **Create repository**를 누릅니다.
5. 빈 저장소 안내의 **uploading an existing file**을 누릅니다. 기존 저장소는 **Add file → Upload files**입니다.
6. ZIP을 먼저 압축 해제합니다. `haebit-ecosystem` 폴더 **안의 내용 전체**를 업로드 영역으로 끌어 넣습니다.
7. 화면의 파일 목록에 `package.json`, `server.js`, `public/` 등이 있는지 확인합니다.
8. 아래 Commit changes에 `첫 수업 앱 올리기`를 입력하고 **Commit changes**를 누릅니다.

**ZIP 자체를 GitHub에 올리면 실행되지 않습니다.**
`package.json`이 저장소 첫 화면에 보여야 합니다. 폴더를 한 겹 더 올리지 않도록 주의하세요.
웹 업로드 제한에 맞추어 ZIP은 100개 미만의 파일로 구성했고 숨김 파일을 제외했습니다.
파일 수 경고가 뜨면 업로드 대기 목록을 비운 후 새 ZIP의 내용만 다시 올려 주세요.
`node_modules`는 올리지 않습니다. 실제 PIN이 들어 있는 `.env`도 올리지 않습니다.

## Render에 배포하기

1. [Render](https://render.com/)에 로그인합니다.
2. **New → Web Service**를 선택합니다. **Static Site가 아닙니다.**
3. GitHub를 연결하고 방금 만든 저장소를 선택합니다. 목록에 없으면 저장소 접근 권한을 허용합니다.
4. 아래와 같이 설정합니다.

| 항목 | 입력 값 |
| --- | --- |
| Name | `haebit-ecosystem` 등 원하는 이름 |
| Language / Runtime | Node |
| Branch | `main` |
| Root Directory | 비워 둠 (저장소 루트에 package.json이 있는 경우) |
| Build Command | `npm install` |
| Start Command | `npm start` |
| Health Check Path | `/health` |

5. Environment Variables에서 **Add Environment Variable**을 눌러 다음을 입력합니다.

| Key | Value |
| --- | --- |
| `TEACHER_PIN` | 선생님만 아는 PIN (예: 직접 정한 6자리 이상) |

6. 플랜을 확인하고 **Create Web Service / Deploy Web Service**를 누릅니다.
7. 로그에 서버가 준비되었다는 안내가 뜨고 상태가 **Live**가 되면 위쪽 서비스 주소를 엽니다.
8. `https://서비스이름.onrender.com/teacher`에서 PIN으로 입장합니다.
9. 학생은 `https://서비스이름.onrender.com/student`를 사용합니다.

`PORT`는 Render가 지정합니다. 별도로 바꿀 필요가 없습니다. Socket.IO는 HTTP와 같은 포트를 사용합니다.
이 앱은 서버 메모리를 사용하므로 **인스턴스는 1개**로 운영하세요. 여러 인스턴스로 늘리면 수업 상태가 공유되지 않습니다.

## 수업에서 사용하기

### 선생님 — 통지서 → 선택 결과 → 선택한 이유

1. `/teacher`에서 PIN을 입력합니다.
2. **새 수업 시작하기**를 누르면 **해빛 생태계 주식회사 입장 화면**이 나옵니다. 큰 참여 코드와 입장 현황이 표시됩니다. 아직 인사 요청과 학생 선택 화면은 열리지 않습니다.
3. 학생들에게 학생 주소와 참여 코드를 알려 줍니다. 학생이 들어오면 해당 번호가 초록색으로 표시됩니다. 접속이 끊기면 다시 대기 색으로 바뀝니다.
4. 입장을 확인한 뒤 **입장 확인 · 다음 →**을 누릅니다. 결석 등으로 27명보다 적어도 선생님이 진행할 수 있습니다. 자동으로 넘어가지 않습니다.
5. **첫날부터 사건 발생!** 화면에서 해빛이가 이름표와 부서표가 뒤섞인 상황을 타이핑으로 설명하고 도움을 요청합니다. 학생들은 이때도 대기합니다.
6. **해빛이가 되어 인사발령 시작 →**을 누르면 첫 통지서가 등장하고 학생 선택 화면이 함께 열립니다.
7. 아래 응답 수를 확인합니다. 응답이나 추가 입장이 있어도 통지서와 이야기 타이핑이 처음부터 다시 시작되지 않습니다.
8. **집계 마감하고 결과 보기 →**를 누릅니다. 확인창에서 마감하면 별도 화면 중앙에 막대그래프가 펼쳐집니다. 아직 선택 이유는 나오지 않습니다.
9. **선택 이유 펼치기 →**를 누르면 이유 화면으로 바뀌고 이유 카드가 차례로 떠오릅니다. 생물별 버튼을 눌러 각각의 이유를 확인합니다.
10. 이야기를 나눈 뒤 **다음 인사 요청으로 이동 →**를 누릅니다. 두 번째와 세 번째 요청은 새 통지서로 시작하며 입장 안내와 도입 이야기를 반복하지 않습니다.
11. 세 번째 이유까지 본 뒤 **활동 종료 · 전체 결과 보기**를 누릅니다. 교사·학생 화면에 완료 도장이 찍힙니다.

- `설명 바로 보기` / `이야기 다시 듣기`: 도입 타이핑을 바로 표시하거나 다시 재생합니다.
- `문장 바로 보기`: 타이핑을 기다리지 않고 문장을 모두 표시합니다.
- `통지서 다시 읽기`: 현재 통지서의 등장과 타이핑을 다시 재생합니다. 학생 응답은 바뀌지 않습니다.
- `선택 결과로 돌아가기`: 이유 화면에서 막대그래프로 돌아갑니다. 응답을 다시 열지 않습니다.
- `전체 화면`: 브라우저 전체 화면으로 보여 줍니다. F11도 사용할 수 있습니다.
- `교사용 기록 · 설정`: 실시간 선택 현황, 이유 집계, 자유 의견, 이전 결과, 전체 결과, 종료, 초기화를 확인합니다. 학생 의견은 이 교사 전용 기록 창에만 표시됩니다. 결과 공개 화면에는 학생 번호나 자유 의견이 나오지 않습니다. 입장 화면의 번호는 접속 확인용입니다.

전자칠판에서는 `전체 화면` 버튼이나 F11을 누르면 주소창까지 숨기고 더 크게 볼 수 있습니다. 교사 화면은 화면 너비와 높이에 맞춰 글씨·그래프를 확대하고 마지막 전체 집계까지 스크롤 없이 표시합니다. 교사 화면의 본문·버튼·숫자는 Noto Sans KR 기반 고딕으로 통일했습니다. 회사 입장 제목과 통지서 제목에만 고운바탕 계열을 사용합니다. 통지서 본문은 FHD에서 약 47px이며 두 번째 요청 문장은 굵게 표시합니다. 이야기 줄간격은 1.65, 통지서 본문은 1.7입니다. 그래프는 화면 중앙에 모았습니다.

기록 창에는 교사에게만 필요한 정보가 있으므로 학급 화면에 보여 주기 전 내용을 확인하세요.
전원이 제출하지 않아도 마감할 수 있습니다. 통지서 → 마감 후 막대그래프 → 이유 공개 → 다음 요청 순서를 지킵니다.
`새 수업 초기화`는 확인 후 기존 방과 응답을 삭제하고 **새 코드**를 만듭니다.
중간에 `수업 종료`를 누르면 현재 요청을 마감하고 활동을 끝냅니다. 미진행 요청에는 “미진행”이 표시됩니다.

### 학생

1. 참여 코드 4자리를 입력합니다.
2. 1~27번 중 자기 번호를 누릅니다. 이름을 입력하지 않습니다.
3. 입장 후 고개를 들고 전자칠판의 해빛이 이야기를 듣습니다. 선생님이 시작하면 크롬북에는 생물 선택지만 열립니다. 상황과 통지서 본문은 전자칠판에서 확인합니다. **이유 고르기**를 누릅니다.
4. 상황에 맞는 이유 하나를 고릅니다. 세 요청은 서로 다른 이유 선택지를 사용합니다. 원하는 친구만 40자 이내로 생각을 더 씁니다.
5. **인사발령 제출하기**를 누릅니다. 공식 접수증에 **인사발령 완료** 도장이 찍힙니다. 정답 판정이 아니라 생각을 접수했다는 뜻입니다.
6. 제출 후에는 변경할 수 없습니다. 교사가 마감하면 칠판을 보라는 안내로 바뀝니다.

선택을 바꾸려면 제출 전에 `생물 다시 고르기`를 사용합니다.
자유 의견을 쓰지 않아도 제출할 수 있습니다.
응답 중 다른 친구의 선택 수, 이유, 자유 의견은 학생에게 전달되지 않습니다.
마감 후 학생 화면에는 집계 완료와 칠판을 보라는 안내만 표시됩니다. 결과 그래프와 이유 집계는 교사 화면에서 함께 봅니다.

## 새로고침과 연결 복구

- 학생의 참여 코드·번호·무작위 복구 토큰을 해당 브라우저에 저장합니다.
- 학생이 새로고침하면 현재 요청과 제출 상태가 복원됩니다.
- 제출한 뒤 새로고침하거나 다른 탭에서 접속해도 서버가 재제출을 막습니다.
- 같은 브라우저의 다른 탭에서 연결하면 최신 탭이 연결을 이어받습니다. 이전 탭은 연결 이전 안내가 뜨고 제출 권한을 잃습니다.
- 다른 브라우저에서 이미 접속 중인 번호를 고르면 경고합니다. 끊긴 번호는 다시 접속할 수 있으며 기존 응답은 계속 잠겨 있습니다.
- 늦게 들어온 학생은 현재 입장 대기·열린 요청·칠판 보기 안내로 바로 들어갑니다.
- 교사도 같은 브라우저에서 새로고침하면 인증과 방을 복원합니다. 인증은 12시간 유효합니다. 입장·이야기·선택 결과·이유 화면의 단계도 서버에서 복원됩니다.
- 학생 번호 방식은 실제 신원 인증이 아니므로 학생들이 자기 번호를 선택하도록 안내해 주세요.

## 로컬 실행 — 선택 사항

Node.js 22 이상을 설치한 컴퓨터에서 프로젝트 폴더를 엽니다.

```bash
npm install
```

macOS / Linux:

```bash
TEACHER_PIN=내가정한PIN npm start
```

Windows PowerShell:

```powershell
$env:TEACHER_PIN="내가정한PIN"
npm start
```

Windows 명령 프롬프트:

```bat
set TEACHER_PIN=내가정한PIN
npm start
```

브라우저에서 `http://localhost:3000`을 엽니다.
이 앱은 `.env` 파일을 자동으로 읽지 않습니다. 위 명령 또는 Render 환경 변수로 지정하세요.

## 서버 메모리와 배포 확인

수업 상태는 데이터베이스 없이 서버 메모리에만 저장됩니다.
서버 재시작·배포 시 수업방과 응답이 사라집니다. 브라우저에 남은 오래된 코드로 접속하면 새 코드로 들어오도록 안내합니다.
서버를 수업 중 재배포하지 마세요. 교사 PIN은 서버 로그에 출력하지 않습니다.

Render에서 제공하는 WebSocket을 사용할 수 있게 구성했으며 로컬 WebSocket 연결은 검증했습니다.
이번 수정본은 실제 Render 서비스에 반영하지 않았으므로, 업데이트 후 다음 순서로 확인해 주세요.

1. 교사 방 생성 → 다른 기기에서 학생 두 명 입장
2. 학생 응답 → 교사 화면의 즉시 집계
3. 교사 마감 → 교사 화면에 결과 공개, 학생 화면에는 칠판 보기 안내
4. 다음 요청 → 두 학생 화면의 동시 이동

플랜에 따라 유휴 서버가 쉬었다가 시작될 수 있으므로 수업 전에 주소를 열고 두 기기로 확인하세요. 현재 플랜의 조건은 Render 화면에서 확인합니다.

공식 참고: [Node/Express 배포](https://render.com/docs/deploy-node-express-app), [Web Service와 PORT](https://render.com/docs/web-services), [WebSocket](https://render.com/docs/websocket), [Socket.IO rooms](https://socket.io/docs/v4/rooms/).

## 기존 GitHub / Render 앱 업데이트

현재 GitHub 저장소에서 **Add file → Upload files**를 누르고 수정 ZIP의 폴더 안 내용 전체를 올립니다.
같은 경로의 파일이 새 버전으로 교체됩니다. `public/presentation.js`, `public/presentation.css`, `public/theme.css`, `public/board.css`, `public/fonts/`의 새 글꼴도 함께 올라가야 합니다.
아래 **Commit changes**를 누르면 Render의 자동 배포가 켜진 경우 다시 배포합니다.
자동 배포가 꺼져 있으면 Render에서 **Manual Deploy → Deploy latest commit**을 실행합니다.
배포 후 `/teacher`를 새로고침합니다. 이전 디자인이 남으면 Ctrl+Shift+R을 눌러 주세요.
서버가 다시 시작되므로 새 수업방을 만들고 새 참여 코드를 사용합니다. `TEACHER_PIN` 환경 변수는 그대로 사용하면 됩니다.

미리보기는 입장부터 세 요청·이유·완료 도장까지 실제 수업 순서로 진행합니다. 위쪽의 진행 단계와 완료 도장 미리보기 버튼은 표시하지 않습니다.

## 전자칠판과 크롬북

교사 주요 화면은 브라우저의 가로·세로 공간을 채우고 크기에 맞춰 글꼴·통지서·그래프를 함께 확대합니다.
통지서 본문은 Noto Sans KR 기반 고딕으로 표시합니다. 1280×720에서는 약 31px, FHD에서는 약 47px입니다. 통지서 제목은 고운바탕 계열 40px 기준입니다. 첫 문장은 보통 굵기, 요청 문장은 굵게 표시합니다. 금빛 구분선과 충분한 종이 여백으로 문서 분위기를 살립니다. 그래프는 화면 중앙에 720px 기준 폭으로 모으고 88px 기준의 막대와 연속된 기준선을 사용합니다. 그래프 옆 캐릭터와 말풍선은 제거했습니다. 상단 회사명은 「해빛 생태계 주식회사 인사과」입니다.
1280×720, 1366×768, 1920×1080, 3840×2160에서 입장·이야기·세 통지서·결과·이유·종료 집계를 검증했습니다.
일반적인 가로 화면에서는 주요 수업 장면과 마지막 전체 집계를 스크롤 없이 볼 수 있습니다. 교사 기록 창은 의견 양에 따라 스크롤됩니다.
전자칠판에서는 브라우저 F11 또는 아래 **전체 화면** 버튼을 사용하면 주소창과 탭 영역까지 숨겨 더 크게 볼 수 있습니다.
학생 화면에는 상황 본문과 결과 그래프를 띄우지 않습니다. 생물·이유 선택, 선택적 40자 의견, 제출 상태만 표시합니다.

## 2.5.0 디자인

처음 입장 코드판은 짙은 초록색, 글자와 작은 선은 아이보리·금빛입니다. 이야기·통지서·이유 화면은 종이 배경과 일정한 문서 여백으로 통일했습니다. 큰 둥근 버튼·노란 말풍선·배경 격자는 정리하고 교사 본문·숫자·버튼을 고딕으로 표시합니다. 완료 화면은 짙은 초록 기록지 위에 금빛 완료 도장이 찍힙니다. 홈과 학생 선택 화면도 같은 색·테두리·버튼으로 맞췄습니다. 학생 선택지의 주아체는 유지합니다.
